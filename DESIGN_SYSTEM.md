# Dr. Giju Paul — Personal Brand Website Design System

## 1. Purpose

This design system defines the visual, interaction, content, and implementation principles for the personal branding website of **Dr. Giju Paul**.

The website should consistently communicate:

- Academic authority
- Research credibility
- Innovation
- Higher education leadership
- Technology awareness
- Practical impact
- Professional accessibility

The design language should feel like:

**Academic authority × technological sophistication × editorial minimalism**

The website must not look like:

- A CV
- A university staff profile
- A Word document
- An academic report
- A generic consultancy template
- A flashy technology startup website

## 2. Core Brand Idea

### Signature Brand Narrative

**Research → Knowledge → Innovation → Impact**

This sequence should influence page structure, project storytelling, section transitions, and visual hierarchy.

### Brand Positioning

**Dr. Giju Paul is a researcher, academic leader, author, trainer and innovation strategist who transforms research into knowledge, innovation, products and measurable impact.**

### Supporting Positioning Line

**Advancing research from academic inquiry to practical impact through methodology, technology, innovation and higher-education leadership.**

## 3. Brand Personality

The visual and verbal identity should feel:

- Credible
- Intelligent
- Calm
- Contemporary
- Research-oriented
- Premium
- Global
- Practical
- Forward-looking
- Human

Avoid:

- Excessive corporate language
- Over-decoration
- Aggressive gradients
- Neon visual effects
- Dense academic text blocks
- Decorative elements without purpose
- Overuse of icons
- Overuse of animation

## 4. Color System

### Primary Colors

**Midnight Navy** — `#0A1424`  
Use for hero backgrounds, navigation, footer, and high-authority visual areas.

**Deep Navy** — `#102033`  
Use for cards, secondary dark backgrounds, and hover states.

**Research Teal** — `#1AA7A1`  
Use for accent text, buttons, data points, links, and active navigation.

**Research Teal Dark** — `#0F7773`

### Accent Color

**Subtle Gold** — `#D6B36A`  
Use sparingly for fine rules, premium highlights, small badges, section markers, and decorative lines.

### Neutral Colors

- Warm White — `#F8F7F3`
- White — `#FFFFFF`
- Cool Gray 100 — `#ECEFF2`
- Cool Gray 300 — `#C9D0D8`
- Cool Gray 600 — `#667085`
- Charcoal — `#1B1D21`

### Usage Balance

Recommended approximate balance:

- 55–65% white / warm white
- 20–30% navy / charcoal
- 8–12% teal
- 2–5% gold

Dark sections should be reserved for hero, signature framework, featured projects, collaboration CTA, and footer.

## 5. Typography

### Typography Strategy

Use an **editorial serif** for large display headlines, selected section titles, pull quotes, and publication highlights.

Use a **modern sans serif** for navigation, body text, buttons, labels, cards, metadata, and forms.

### Recommended Font Pairing

**Cormorant Garamond**  
Use for editorial/display typography.

Fallback: Georgia, Times New Roman, serif.

**Inter**  
Use for interface and body typography.

Fallback: Arial, Helvetica, sans-serif.

### Type Scale

**Display / Hero**  
`clamp(3rem, 7vw, 6.5rem)`  
Weight: 600–700  
Line-height: 0.95–1.05

**H1**  
`clamp(2.5rem, 5vw, 4.75rem)`  
Line-height: 1.05

**H2**  
`clamp(2rem, 4vw, 3.5rem)`  
Line-height: 1.1

**H3**  
`clamp(1.5rem, 2.5vw, 2.25rem)`  
Line-height: 1.2

**H4**  
`1.25rem–1.5rem`  
Line-height: 1.25

**Body Large**  
`1.125rem–1.25rem`  
Line-height: 1.65

**Body**  
`1rem`  
Line-height: 1.7

**Small / Metadata**  
`0.875rem`  
Line-height: 1.5

## 6. Heading Hierarchy

Each page must have:

- One `H1`
- Major sections as `H2`
- Subsections as `H3`
- Card titles as `H3` or `H4`

Do not skip heading levels for visual reasons.

Headings should be concise, descriptive, and SEO/GEO-friendly.

## 7. Spacing System

Use an 8px base spacing system.

- 4px — micro
- 8px — xs
- 12px — compact
- 16px — sm
- 24px — md
- 32px — lg
- 48px — xl
- 64px — 2xl
- 96px — 3xl
- 128px — 4xl

Section vertical spacing:

- Desktop: 96–144px
- Tablet: 72–96px
- Mobile: 56–72px

Generous whitespace is a core brand characteristic.

## 8. Grid System

### Desktop
- Maximum content width: 1280px
- 12-column grid
- Gutter: 24–32px
- Side padding: 32–48px

### Tablet
- 8-column grid
- Side padding: 24–32px

### Mobile
- 4-column grid
- Side padding: 18–24px

## 9. Layout Principles

Prefer:

- Editorial asymmetry
- Strong alignment
- Alternating dark/light sections
- Wide whitespace
- Full-bleed project imagery
- Controlled content density

Avoid:

- Center-aligning every section
- Equal-height blocks everywhere
- Repetitive card grids on every page
- Excessive boxed layouts
- Multiple competing CTAs

## 10. Border Radius

Recommended:

- Buttons: 999px for pill CTAs
- Cards: 20px
- Small UI: 12px
- Images: 20px
- Tags: 999px

## 11. Shadows

Default card shadow:

`0 16px 40px rgba(10, 20, 36, 0.08)`

Hover shadow:

`0 20px 50px rgba(10, 20, 36, 0.12)`

Dark cards may use borders instead of shadows.

## 14. Card System

Cards are used for:

- Research areas
- Projects
- Publications
- Training programmes
- Speaking engagements
- Insights
- Achievements

Base card content:
- Category label
- Title
- Short summary
- Metadata

## 18. Image Treatment

Images should feel:

- Editorial
- Premium
- Documentary
- Research-focused
- International
- Human

Preferred:
- Professional portraits
- Research environments
- Training sessions
- University settings
- Field research
- Conference photography
- Innovation prototypes
- Digital visual overlays used sparingly

Avoid:
- Generic handshake stock images
- Excessive futuristic holograms
- Low-quality screenshots
- Images containing unreadable AI-generated text

Default image radius: 20px unless full bleed.

## 19. Portrait Strategy

Primary portrait style:

- Professional
- Natural expression
- Clean background
- Strong but approachable
- Editorial lighting
- Medium crop / environmental portrait

Hero portrait should feel like a magazine/profile photograph rather than an ID or corporate headshot.

## 20. Iconography

Recommended: **Lucide Icons**

Style:
- Outline
- 1.5–2px stroke
- Minimal
- Consistent sizing

Typical sizes:
- 18px inline
- 24px card
- 32px feature
- 40px maximum for major service blocks

## 21. Animation Principles

Allowed:

- Fade + slight upward reveal
- Image scale on hover
- Arrow movement
- Number count-up where useful
- Progress line reveal
- Subtle section transitions

Timing:
`180ms–500ms`

Preferred easing:
`cubic-bezier(0.22, 1, 0.36, 1)`

Avoid bouncing, spinning, flashing, long entrances, and decorative auto-play motion.

Respect `prefers-reduced-motion`.

## 22. Responsive Breakpoints

Recommended:

- Mobile: `< 640px`
- Large mobile / small tablet: `640px+`
- Tablet: `768px+`
- Small desktop: `1024px+`
- Desktop: `1280px+`
- Large desktop: `1536px+`

Design mobile-first.

## 28. SEO Design Principles

Every page should support:

- One clear H1
- Descriptive title tag
- Meta description
- Canonical URL
- OpenGraph data
- Structured data
- Internal links
- Accessible image alt text
- Logical heading hierarchy
- Descriptive URLs
- Breadcrumbs on deeper pages

## 29. GEO / AEO Principles

Content should answer likely questions explicitly.

Examples:

### Who is Dr. Giju Paul?
Use a concise factual paragraph near the top of the About page.

### What are Dr. Giju Paul's areas of expertise?
Provide a structured list.

### What research methodology support does Dr. Giju Paul provide?
Use answer-first content.

### What is Micro Research?
Provide a direct definition before elaboration.

### What is Research-to-Product?
Provide a clear explanation and examples.

## 30. Structured Data Strategy

- `Person`
- `ProfilePage`
- `WebSite`
- `Article`
- `BlogPosting`
- `ScholarlyArticle`
- `Course`
- `Event`
- `BreadcrumbList`

Use structured data only where content genuinely supports it.

## 31. Accessibility

Minimum requirements:

- WCAG AA color contrast
- Keyboard-accessible navigation
- Visible focus states
- Semantic HTML
- Form labels
- Alt text
- No text embedded only in images
- Proper button/link semantics
- Reduced-motion support
- Logical reading order
- 44px minimum touch targets

## 32. Performance Principles

Prioritize:

- Server-rendered essential content
- Optimized images
- Minimal JavaScript
- Lazy loading below the fold
- Efficient font loading
- Reusable components
- No unnecessary animation libraries
- No large client-side bundles

Targets:

- Lighthouse accessibility: 90+
- Lighthouse SEO: 95+
- Lighthouse performance: 90+ where practical

## 37. Component Change Policy

When modifying an approved section:

1. Identify affected components.
2. Identify affected routes/pages.
3. Preserve unrelated approved components.
4. Do not silently remove functionality.
5. Keep styling consistent with this design system.
6. Record structural changes in project documentation.

## 38. Approval Principle

Once a page or component is approved:

- Treat it as stable.
- Modify only what is requested.
- Avoid redesigning unrelated areas.
- Preserve visual rhythm and spacing.
- Maintain consistent tokens and components.

## 39. Final Design Standard

Every page should feel like it belongs to the same system.

The user experience should consistently reinforce:

**Research → Knowledge → Innovation → Impact**

The finished site should feel like the digital home of a:

**researcher + academic leader + innovation strategist + thought leader**

rather than a résumé displayed on the web.
